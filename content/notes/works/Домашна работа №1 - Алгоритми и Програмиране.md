## Task

_The standard insertion sort procedure uses a linear search through the sorted subarray. Rework the algorithm to use binary search instead. Besides the program, write the pseudocode. Proof both algorithm correctness and running time._

### Pseudocode: Insertion Sort with Binary Search

```pseudo
	\begin{algorithm}
	\caption{Insertion Sort /w Binary Search}
	\begin{algorithmic}
	\Procedure{BinarySearch}{$A, r, x$}
	    \State $l \gets 1$
		\While{$r >= l$}
			\State $m \gets l + \lfloor(r-l)/2\rfloor$
			\If{$A[m] < x$}
				\State $l \gets m + 1$
			\Else
				\State $r \gets m - 1$
			\EndIf
		\EndWhile
		\Return $l$
	\EndProcedure
	\Procedure{InsertionSort}{$A$}
		\For{$i \gets 2$ \To $A.length$}
			\State $x \gets A[i]$
			\State $p \gets $ \Call{BinarySearch}{$A, i, x$}		
			
			\For{$j \gets i$ \DownTo $p$}
				\State  $A[j] \gets A[j-1]$
            \EndFor

			\State $A[p] \gets x$
        \EndFor
    \EndProcedure
	\end{algorithmic}
	\end{algorithm}
```

### Proof of correctness

#### Binary Search

We define the procedure `BinarySearch` that accepts the following arguments:
- $A$ - a sorted array of values
- $[l; r]$ - range from $l$ to $r$, that we are searching through
- $x$ - the value we are looking for

The goal of the algorithm is to provide a position, where $x$ could be inserted inside $A$, while keeping the array sorted (if "enough room is made for $x$").

**Initialisation**: We set $l$ to be the start of the sorted array $A[a_l, a_{l+1}, ..., a_{r-1}]$ is sorted and we assume that $l < r$.

**Maintenance:** The while loop works by halving the input by getting the middle element $A_{m}, (\text{ where } m = {l + \lfloor(r-l)/2\rfloor})$ of the current range $[l; r]$ and comparing it to the search value - $x$.

- If the middle element $A_m < x$, then the $x$ must be inserted "to the right" of $A_m$ by setting $l = (l + \lfloor(r-l)/2\rfloor) + 1$. This case also prevents $x$ being added to "the left" of $A_m$ when $x > $A_m$ 
- If $A_m >= x$, we continue to search in the "left" half by reducing $r$ by $1$

**Termination:** The loop terminates when $r < l$ and at this point $l$ contains the value of the position where $x$ should be inserted in $A$. This is because the final iteration sets $l$ to a value that is either one greater than the last position of $A_m$ or the same value of $l$ that couldn't satisfy the $r >= l$ condition.

#### Insertion Sort

We define the procedure `InsertionSort` that accepts:
- $A$ an array to be sorted

The goal of the algorithm is to sort $A$.

**Initialisation**: We start iterating over the elements of $A$ by skipping the first element and the subarray with elements at position $1,...,i$ inside the loop is sorted.

**Maintenance**: Each iteration the algorithm performs the following tasks:
- Uses the previously defined `BinarySearch` procedure to find suitable position $p$ in $A$ of the value $A[i]$ without disrupting the sorted order of the subarray $A_{1, ..., i}$
- Move the elements from $A_{p, ..., i}$ one position "to the right" to make room for $x$ and its new position $p$. This step also doesn't disrupt the already sorted subarray $A_{1, ..., i}$
- As a last step we set $A[p]$ to be equal to $A[i]$

**Termination**: The loop and algorithm exits when all elements from $A$ have been iterated over. At this point the entire array is sorted in a non-decreasing order.

### Time complexity

#### Binary Search

The recurrence relation for the time complexity of the binary search variation used here is:

$$
T(n) = T\big(\frac{n}{2}\big) + k
$$
where $n$ are the number of elements inside the range and $k$ is the constant time required to compare the middle value $A_m$ and $x$.

If we solve the recurrence relation we get:

$$T(n) = O(\log_2n)$$

#### Insertion Sort

To find the overall time complexity of this variation of insertion sort, we consider both procedures as one algorithm. For each element in the array we perform binary search with time complexity of $O(\log_2n)$ and we shift elements $O(p)$ times. The time complexity is dominated by the shifting operation and we can represent it with:

$$
T(n) = \sum_{i=1}^{n}O(p)
$$
which simplified gives us:

$$
\begin{align}
 T(n) &= O(1) + O(2) + ... + O(n) = \\ \\
&  = O\bigg(\frac{n(n-1)}{2}\bigg)
\end{align}
$$

The term above resolves to $O(n^2)$, which is the overall time complexity of the insertion sort variation. Even though we are optimising the searching of suitable position to put unsorted values inside the sorted subarray, the time complexity still remains $O(n^2)$.

### C++ Implementation

```cpp
int binary_search(const int *arr, int r, int x) {
	int l = 0;
    while (r >= l) {
        unsigned m = l + ((r - l) / 2);

        if (arr[m] < x) {
            l = m + 1;
        } else {
            r = m - 1;
        }
    }

    return l;
}

void insertion_sort(int *a, unsigned n) {
    for(int i = 1; i < n; i++) {
        int x = a[i];
        
        int p = binary_search(a, i, x);
        
        for (int j = i; j > p; j--) {
            a[j] = a[j-1];
        }

        a[p] = x;
    }
}
```
